# 旅行状态与记忆边界

`travel-continuity.ts` 根据 `travel-state` 和张起灵私聊中的旅行系统事件生成当前状态。`storage.travelSnapshot()` 在同一 IndexedDB 只读事务中读取两者，与原有旅行状态及通知的原子写入配合。

- `currentId` 存在：仍在途中，即使预计结束时间已过，或上一趟已经归来。
- 本次已结束且有对应 `tripId` 的有效 `travel_return` 聊天事件：确认归来。
- 旅行记录存在，但本次归来通知缺失、隐藏或撤回：保持“归来尚未确认”，不从手记、普通角色发言或预计时间推断已经回家。旧备份也采用此规则。
- 出发预告不等于已经出发。归来不等于已与用户线下见面。

私聊和通话在历史摘要、用户保存的记忆之后加入独立的当前状态段；包含张起灵的普通群聊和群内主动消息只接收公开旅途上下文。其他群聊、独立约会和剧本不会因此获得他的私聊或旅行记忆。

朋友圈使用最近六条公开动态和本次已发生的有限旅途事件，不读取私聊正文、私聊摘要、旅行留言、私人手记、未完事项或约会内容。正文、配图描述和 NPC 评论均受当前旅行事实约束。私人日记仍可参考张起灵私聊与私人旅途资料。

不修改既有聊天、朋友圈或摘要。旅行计时、归来通知写入和进行中场景的旅行延后规则保持原有实现。

`npm run test:travel-continuity` 使用独立浏览器存储和截获的测试接口，校验多趟旅行、预计时间、缺失通知、刷新恢复，以及实际私聊、群聊和朋友圈请求的状态及隐私边界。测试不调用真实付费模型；不能替代各用户所选模型的实际回复质量验证。

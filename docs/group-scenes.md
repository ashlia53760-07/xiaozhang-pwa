# 群聊线下与多人约会

## 使用

1. 进入已有群聊，打开「功能 → 线下」或「功能 → 心动约会」。每个群独立保存进度；返回聊天保留现场，刷新后可以继续。
2. 线下填写地点、时间、环境。约会可以选择预设，或粘贴最长 6000 字的自定义剧本（场景、人物安排、开场、文风均可）。
3. 展开「同行人数 · 接话设置」，沿用群聊规则，或选择自然、全员、指定角色接话。全员模式逐人请求，最多 16 位；指定模式需勾选至少一人。每人使用其联系人 API 配置或现有的共享配置。
4. 每位角色看到前面的现场以及本轮已经发生的回应，分别以自己的身份落笔。可以「停止接话」，成功楼层已逐条保存。中断后用底部菜单「重新生成」补齐缺少的成员；完整一轮后的重新生成仅替换最后一位角色的回应，失败保留原文。
5. 底部菜单支持续写、多选删除；楼层长按/右键支持编辑及带保存节点的回退。回退到用户层后「重新生成」可重新演绎该轮。楼层改动不自动调用模型。

## 衔接与归属

- 仅使用本群公开的背景、世界书、公告、成员公开关系和启用的共同记忆，不读取私聊历史、人设补充、个人日历或其他群的资料。
- 线下每轮参考本群近期线上内容，结束时把见面摘要写入原群，方便线上接续。线下记录跨次见面保留。
- 约会在开场时捕捉本群近期公开背景；之后以独立剧本和本场记录为准。剧情不自动变成日常事实。手动「保存为回忆」只写入原群共同记忆。
- 长历史沿用应用的阈值摘要机制，每群/每场约会独立缓存。摘要是资料，近期原文和用户更正优先。达到阈值会增加一次摘要 API 请求。
- 全员接话按人数逐次调用 API；配置缺失时显示问题并保留尚未发送的输入，不伪造离线角色回复。
- 新加入的成员从下次新开现场起参与；当前场景中的禁用成员停止接话。已保存楼层保留原发言者信息。

## 数据与兼容

- 群线下：关系档案数据库 `kv` 中的 `group-life:<groupId>`，包含成员、现场和楼层。
- 群约会：兼容原 `date-sessions`，新增 `groupId`、成员、接话方式、开场背景和递增修订号；旧私聊约会继续按原角色读取，缺少角色归属的旧记录仍属于张起灵。
- 群剧场写入在同一 IndexedDB 事务中核对修订号，防止旧页面的生成、背景或设置覆盖更新后的现场。楼层操作也核对当前原文，并在回退前保存完整关系档案节点。
- 整机备份新增可选 `groupLifeScenes`；群约会包含在原 `dateSessions`。关系档案节点包含群线下、群约会、群资料及其他既有关系数据。导出不含 API Key。恢复沿用保留本机冲突记录的合并规则。
- 不升级 DB_VERSION，不改备份版本，不修改 PC 或 Android 工程。

## 验证

`npm run build` 后运行 `npm run preview -- --host 127.0.0.1 --port 4180`，另一个终端执行 `npm run test:group-scenes`；可用 `GROUP_SCENE_TEST_URL` 指向其他预览或正式站。

测试使用独立 Chrome 临时上下文、合成 IndexedDB 和拦截的模拟模型 API，覆盖多人衔接、隔离、角色选择、失败与停止补齐、编辑回退、节点、刷新、五主题与屏宽、并发版本检查、真实备份导入和 16 人同场。报告与截图仅写入被 Git 忽略的 `.local-review/group-scenes/`。未进行 Android 真机测试。
